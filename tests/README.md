# Автоматические проверки

Четыре набора, без зависимостей — только Node.js. Вместе — 91 проверка.

| Набор | Проверок | Предмет |
|---|---|---|
| `tests/malumot.test.js` | 44 | единый модуль данных `malumot.js` (правила Д-1…Д-8, `docs/TZ.md`, раздел 3) и словарь перевода `tarjima.js` |
| `tests/nazorat.test.js` | 21 | модель здания, данные контроля доступа, индекс контроля, совпадение списка ролей во всех источниках |
| `tests/sahifalar.test.js` | 10 | целостность навигации и страниц: дерево разделов, ссылки, ленты вкладок, метка версии, синтаксис встроенных скриптов, матрицы ролей |
| `tests/server.test.js` | 16 | REST-контракт `server/server.js`: сессия, вход, чтение и запись, права по разделам |

## Запуск

```
node tests/malumot.test.js
node tests/nazorat.test.js
node tests/sahifalar.test.js
node tests/server.test.js
```

Раннер печатает результат по группам (`[OK]` / `[FAIL]`, в наборе страниц —
`[OK]` / `[XATO]`), в конце — итоговую строку: `Итог: пройдено N, провалено M`
либо `Yakun: o'tdi N, yiqildi M`. При любом провале код выхода — 1.

`server.test.js` сам поднимает сервер на порту 8791 и останавливает его по
окончании. Все наборы работают на условных демонстрационных данных: локальный
реестр из каталога `mahalliy/` вне браузера не читается, поэтому результаты
одинаковы на любом компьютере.

## `malumot.test.js` — что покрыто

| Группа | Предмет |
|---|---|
| 1 | `tasnifla()` — обе стороны каждого порога категорий (0/1, 30/31, 90/91, 180/181), большие и отрицательные значения |
| 2 | `zaxiraHisobi()` — резерв, необеспеченный остаток, покрытие: qarz>baho, qarz<baho, qarz=0 (деление на ноль), округление до 0,1 |
| 3 | `pul()` / `son()` — порог млн/млрд на 999,9/1000, срез «,00», десятичная запятая, группировка ru-RU |
| 4 | Реестр `OBYEKT_INDEKS` — разрешение всех `obyektId` вторичных коллекций, префикс `?` для битого id, `joyNomi` с/без разделителя |
| 5 | Производные поля `YOZUVLAR` — `jami`, соответствие категории дням, `zaxira`, `qoplash`, `ochiqQoldiq` + контрольные точки датасета |
| 6 | `moslikTekshiruvi()` — пусто на чистых данных; мутационные кейсы (рассинхрон `jami`, битый `obyektId` в `HODISALAR`, статус `UCHASTKALAR`) со свежей перезагрузкой модуля между кейсами |
| 7 | `tasnifStatistikasi()` — сходимость сумм с `jamiQarz()` / `jamiZaxira()`, присутствие пустых категорий |
| 8 | `tarjima.js` — модуль парсится, ключей ≥ 800, дублей нет (построчный разбор исходника, а не `Object.keys`) |

## Особенности

- `zaxiraHisobi` — приватная функция модуля (в `window.MKB_DATA` не
  экспортируется). Случай `qarz = 0` через данные недостижим, поэтому тест
  извлекает исходник функции из `malumot.js` балансным сканом скобок и
  исполняет реальный код. Если функцию когда-нибудь экспортируют, тест
  «private, не в экспортах» упадёт и напомнит перевести группу на прямой вызов.
- Тесты с пометкой «характеризация» фиксируют фактическое поведение
  (отрицательные дни в `tasnifla()` дают «yaxshi»; `pul(1500)` даёт
  «1,50 mlrd so'm» — срезается только точный хвост «,00»), чтобы его
  изменение не прошло незамеченным.
- Мутационные тесты группы 6 требуют от сторожа ровно одну ошибку с нужным
  текстом и id — сторож, который не умеет краснеть, бесполезен.

## `sahifalar.test.js` — что покрыто

Набор читает файлы страниц, `yadro/daraxt.js`, `yadro/app.js` и
`server/server.js` как текст; браузер и сервер ему не нужны. Страницы, имя
которых начинается с `_`, в проверку не входят.

| Группа | Предмет |
|---|---|
| 1. Дерево навигации | каждый файл из `MKB_DARAXT` (пункты боковой навигации) существует; каждый файл из `MKB_ICHKI` (внутренние страницы раздела) существует; у каждого ключа `BOLIMLAR` есть непустая ветка дерева, а разделов не больше девяти; `data-sahifa` каждой страницы из дерева совпадает с разделом, к которому она отнесена |
| 2. Ссылки | все `href` и `src` страниц на `.html`, `.js`, `.css`, `.webp`, `.jpg`, `.svg`, а также имена страниц в строках сценариев ведут на существующие файлы; то же — для имён страниц в `yadro/app.js`, `yadro/qollanma.js`, `yadro/api.js`; каждая вкладка ленты `nav.bolim-tablar` ведёт на существующую страницу того же раздела (ленты карточек с подстановкой идентификатора, `data-id-qoshib`, пропускаются) |
| 3. Общие требования | на всех страницах одна метка версии `?v=…`; в `ROL_RUXSAT` клиента и `ROL_BOLIMLAR` сервера нет упразднённых ключей разделов `arxiv`, `xarita`, `sugurta`, `hujjat` |

Набор закрепляет состав из девяти разделов: возврат упразднённого раздела,
ссылка на удалённый экран, страница с чужим ключом раздела или забытая метка
версии дают отказ с именем файла. При добавлении экрана его нужно внести либо в
`MKB_DARAXT`, либо в `MKB_ICHKI` — иначе проверка прав для ссылок на него не
узнает его раздел.
