# Тесты ядра данных

Проверки единого модуля данных `malumot.js` (правила Д-1…Д-8, `docs/TZ.md`,
раздел 3) и словаря перевода `tarjima.js`. Без зависимостей — только Node.js.

## Запуск

```
node tests/malumot.test.js
```

Раннер печатает результат по группам (`[OK]` / `[FAIL]`), в конце — строку
`Итог: пройдено N, провалено M`. При любом провале код выхода — 1.

## Что покрыто

| Группа | Предмет |
|---|---|
| 1 | `tasnifla()` — обе стороны каждого порога категорий (0/1, 30/31, 90/91, 180/181), большие и отрицательные значения |
| 2 | `zaxiraHisobi()` — резерв, необеспеченный остаток, покрытие: qarz>baho, qarz<baho, qarz=0 (деление на ноль), округление до 0,1 |
| 3 | `pul()` / `son()` — порог млн/млрд на 999,9/1000, срез «,00», десятичная запятая, группировка ru-RU |
| 4 | Реестр `OBYEKT_INDEKS` — разрешение всех `obyektId` вторичных коллекций, префикс `?` для битого id, `joyNomi` с/без разделителя |
| 5 | Производные поля `YOZUVLAR` — `jami`, соответствие категории дням, `zaxira`, `qoplash`, `ochiqQoldiq` + контрольные точки датасета |
| 6 | `moslikTekshiruvi()` — пусто на чистых данных; мутационные кейсы (рассинхрон `jami`, битый `obyektId` в `HODISALAR`, статус `UCHASTKALAR`) со свежей перезагрузкой модуля между кейсами |
| 7 | `tasnifStatistikasi()` — сходимость сумм с `jamiQarz()` / `jamiZaxira()`, присутствие пустых категорий |
| 8 | `tarjima.js` — модуль парсится, ключей ≥ 800, дублей нет (построчный разбор исходника, а не `Object.keys`) |

## Особенности

- `zaxiraHisobi` — приватная функция модуля (в `window.MKB_DATA` не
  экспортируется). Случай `qarz = 0` через данные недостижим, поэтому тест
  извлекает исходник функции из `malumot.js` балансным сканом скобок и
  исполняет реальный код. Если функцию когда-нибудь экспортируют, тест
  «private, не в экспортах» упадёт и напомнит перевести группу на прямой вызов.
- Тесты с пометкой «характеризация» фиксируют фактическое поведение
  (отрицательные дни в `tasnifla()` дают «yaxshi»; `pul(1500)` даёт
  «1,50 mlrd so'm» — срезается только точный хвост «,00»), чтобы его
  изменение не прошло незамеченным.
- Мутационные тесты группы 6 требуют от сторожа ровно одну ошибку с нужным
  текстом и id — сторож, который не умеет краснеть, бесполезен.
