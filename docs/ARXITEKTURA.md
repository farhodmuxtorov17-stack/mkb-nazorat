# Система контроля объектов — архитектура

Рабочая система отдела проблемных активов «Микрокредитбанка». Предмет учёта —
физический объект (здание, помещение, участок, транспорт), который банк держит
под контролем: от начала взыскания и приёма на баланс до снятия с контроля и
архива. **116 экранов, 13 разделов, 6 ролей**, статический клиент без сборщика.

### 1.2 Общий каркас страницы

Экраны — плоский список HTML-файлов в корне репозитория, без вложенных папок и
без маршрутизатора: переход между экранами — обычная ссылка. У всех страниц
одинаковый пролог и одинаковый скелет разметки:

```
<link rel="stylesheet" href="yadro/app.css?v=…">
<body data-sahifa="<ключ раздела>">
  <div class="qobiq">
    <nav class="yon" id="yon"></nav>                  ← рельс рисует app.js
    <div class="sahna">
      <header class="shapka" id="shapka"></header>    ← шапку рисует app.js
      <main class="kontent">  … разметка экрана …
```

Порядок подключения одинаков на всех 116 страницах и является требованием, а не
стилем: каждый следующий файл данных дописывает результат предыдущего.

```
yadro/bino.js → malumot.js → malumot-qoshimcha.js → malumot-kengaytma.js →
malumot-kirish.js → malumot-indeks.js → tarjima.js → yadro/ikonlar.js →
yadro/daraxt.js → yadro/chizma.js → yadro/qollanma.js → yadro/api.js → yadro/app.js
```

`yadro/qavat.js` и `yadro/nav3d.js` подключают только два экрана — `obyekt-qavat.html`
и `obyekt-3d.html`. Остальным они не нужны и не грузятся.

Шесть страниц работают вне оболочки и помечены `data-ochiq="1"` — вход,
восстановление и смена пароля, две страницы ошибок и точка входа `index.html`.
Для них `app.js` пропускает проверку прав и не рисует рельс с шапкой.

### 1.3 Сборка экранов

Страницы не правятся по одной: пролог, скелет разметки, порядок скриптов и метка
версии выставляются сборкой одинаково для всего набора. Отсюда два следствия,
видимых прямо в файлах:

- все ссылки на общие файлы несут одну и ту же метку версии (`?v=26082730`),
  поэтому кэш сбрасывается разом по всей системе, а не по одному экрану;
- индекс разделов `yadro/daraxt.js` и реестр экранов `docs/EKRANLAR.md`
  собираются от того же набора страниц, поэтому рельс не может показать пункт,
  которого нет, и не может потерять существующий.

### 1.4 Сервер

`server/server.js` — чистый Node.js, без внешних пакетов:

- отдаёт статику из корня и обслуживает REST `/api/*`;
- при первом запуске засевает хранилища `server/malumotlar/*.json` — 22 коллекции,
  прочитанные из `malumot.js` и `malumot-qoshimcha.js` в изолированном контексте;
- держит токены сессий в памяти, проверяет сессию на каждом запросе;
- пишет журнал действий `amallar.json`, хранит последние 2000 записей.

```
node server/server.js        →  http://localhost:8790
```

Порт переопределяется переменной `PORT`. На статическом хостинге сервера нет —
`api.js` сам переходит в локальный режим, изменения остаются в браузере.

## 2. Оболочка `yadro/app.js`

Единственный файл, который знает про разделы, роли и язык. Он владеет:

- **реестром разделов** `BOLIMLAR` — 12 записей: ключ, ярлык, иконка, входная
  страница. Порядок в массиве и есть порядок рельса;
- **матрицей доступа** `ROL_KALIT`, `ROL_RUXSAT`, `SAHIFA_MAXSUS` (раздел 6);
- **рельсом** `yonChiz()`: группы разворачиваются из `MKB_DARAXT`, пункт без права
  не рисуется вовсе; внизу — настройки, индикатор режима данных и выход;
- **шапкой** `shapkaChiz()`: быстрые пилюли по первым четырём доступным разделам,
  поиск по реестру (`/` — фокус, Enter — переход), переключатель UZ/RU, кнопка
  порядка работы, уведомления, меню профиля, мобильное меню;
- **переводом** `tarjimaQil()`: обход текстовых узлов плюс шесть атрибутов из
  списка `TARJIMA_ATTR` — подсказки полей ввода, всплывающие подписи,
  `aria-label`, `alt` и тексты уведомлений на кнопках.
  Исходный текст запоминается в `WeakMap`, поэтому возврат на узбекский точный.
  Кроме словаря работает список регулярных правил. Прогон повторяется через
  250 и 1000 мс — для содержимого, дорисованного скриптом экрана;
- **движками интерфейса** `MKB.*`: `jadval` (поиск, фильтры, сортировка,
  постраничность, пустое состояние), `forma` (сбор значений и подсветка
  незаполненных обязательных полей), `modal`, `yonPanel`, `toast`, `zanjir`
  (цепочка этапов), `halqa`, `shtrix`, `barlar` (полосы распределения),
  форматирование сумм и чисел.

Точка входа — `DOMContentLoaded`: вставить спрайт, проверить сессию и право на
страницу, нарисовать рельс и шапку, запустить перевод. Без сессии — переход на
`kirish.html`, без права — на `xato-403.html`.

Кнопка «как работать в системе» в шапке открывает боковую панель с порядком
работы для текущей роли из `yadro/qollanma.js`: цель, дневной порядок шагов со
ссылками, зона ответственности, сроки и перечень закрытых разделов. Полная
версия — экран `qollanma.html`.

## 3. Слой данных — порядок загрузки

Пять файлов, каждый дописывает `window.MKB_DATA`. Порядок обязателен.

| # | Файл | Что добавляет |
|---|---|---|
| 0 | `yadro/bino.js` | Модель здания. Публикует `MKBbino`, не трогает `MKB_DATA`, но нужен следующим |
| 1 | `malumot.js` | Ядро: этапы, записи объектов, индекс объектов, осмотры, полисы, оценки, документы, происшествия, задачи, уведомления, сотрудники, регионы, точки карты, форматирование сумм, `moslikTekshiruvi()` |
| 2 | `malumot-qoshimcha.js` | Производные коллекции: судебные заседания, адвокаты, расходы, аренда, реструктуризация — все выводятся из записей, без вторых копий; расширяет `moslikTekshiruvi()` |
| 3 | `malumot-kengaytma.js` | Доводит охват до полного реестра: достраивает записи, осмотры, полисы, оценки, документы, происшествия, задачи и документы, затем пересчитывает сводные показатели и срез по регионам |
| 4 | `malumot-kirish.js` | Модуль контроля доступа: лица, точки доступа (берутся из модели здания), устройства, разрешения, заявки, визиты, события, инциденты, дистанционные сессии, сервисные работы, сводка `kirishJamlama()` |
| 5 | `malumot-indeks.js` | Индекс контроля объекта (раздел 4) |

Объём после полной загрузки: 64 объекта, 187 осмотров, 59 полисов, 88 оценок,
222 документа, 20 архивных записей; по контролю доступа — 362 точки, 1269
устройств, 40 лиц, 171 разрешение, 46 заявок, 128 визитов, 720 событий,
64 инцидента, 28 дистанционных сессий, 52 сервисные работы.

Два правила держат слой связным:

1. **Один источник.** Экраны не хранят собственных массивов: сумма, дата и
   состояние по объекту одинаковы во всех разделах, потому что читаются из
   одного места.
2. **Воспроизводимость.** Достраивание данных детерминировано — фиксированное
   зерно псевдослучайности в каждом файле, системная дата закреплена на
   26 августа 2026 г. Один и тот же объект всегда даёт одни и те же цифры.

`moslikTekshiruvi()` — набор инвариантов поверх загруженных данных: сходимость
сумм, целостность ссылок между коллекциями, соответствие состояния объекта его
этапу. На текущих данных возвращает пустой список нарушений.

## 4. Индекс контроля объекта

Центральный показатель системы, 0–100 %. Он не хранится в записи, а
пересчитывается из текущих данных при каждой загрузке — поэтому не может
разойтись с реальностью. Складывается из пяти проверок:

| Проверка | Вес | Норма |
|---|---|---|
| Актуальность осмотра | 25 | каждые 90 дней; транспорт — 30, участки — 180 |
| Страховая защита | 25 | полис действует, покрытие не ниже оценки |
| Актуальность оценки | 20 | раз в 12 месяцев |
| Полнота документов | 15 | три обязательных документа |
| Контроль доступа | 15 | все точки объекта на связи, нет незакрытых инцидентов |

Просрочка нормы снижает вклад ступенчато: в пределах нормы — полный вес, до
полутора норм — 0,6, до двух — 0,3, дальше — ноль. Уровни: **85 и выше** —
высокий контроль, **70** — устойчивый, **50** — требует внимания, ниже —
критический.

Каждая проверка возвращает не только долю, но и фактическое значение, норму и
причину отклонения. Поэтому карточка объекта показывает не голое число, а то,
чего именно не хватает: «полис истекает через 12 дней», «не хватает кадастрового
документа», «две точки доступа не на связи».

Публичные точки: `MKB_DATA.nazoratIndeksi(объект)` — разбор по проверкам,
`MKB_DATA.nazoratJamlama()` — среднее и распределение по уровням,
`объект.mulk.nazoratBall` — готовый балл для списков и таблиц.

## 5. Модель здания и движки отрисовки

### 5.1 `yadro/bino.js` — модель

Одна геометрическая модель на объект, построенная от его идентификатора и типа:
свёртка имени даёт зерно, зерно — детерминированный генератор, результат
кэшируется. Десять типологий (административное здание, торговый комплекс,
торговая площадь, склад, производство, жилой комплекс, квартира, жилой дом,
транспорт, участок) плюс запасная.

Единица измерения — метр, начало координат — левый верхний угол габарита.
Размеры: наружная стена 0,40 м, перегородка 0,15 м, коридор 2,40 м, дверь
0,95 м, окно 1,70 м, высота этажа 3,60 м. Шестнадцать типов помещений, четыре
состояния: в использовании, свободно, опечатано, в ремонте.

Модель отдаёт этажи, помещения с координатами и площадью, стены, дверные и
оконные проёмы, точки доступа, суммарную площадь и количество помещений.

Из неё читают **три** потребителя — план этажа, трёхмерный навигатор и реестр
точек доступа. Именно поэтому чертёж, объёмный вид и список точек не расходятся
между собой.

### 5.2 `yadro/qavat.js` — план этажа

Архитектурный чертёж в SVG, масштаб 1 м = 10 единиц: сетка осей с разметкой,
стены с толщиной, вырезанные в них проёмы, створки дверей с дугой открывания,
внешние рамы окон, штриховка опечатанных и ремонтируемых помещений, подписи с
площадью, значки точек доступа, размерные цепочки по двум сторонам, масштабная
линейка, стрелка севера и условные обозначения. Помещение выбирается щелчком и
с клавиатуры; щелчок по точке доступа даёт отдельное событие.

### 5.3 `yadro/nav3d.js` — трёхмерный навигатор

Собственный движок поверх canvas 2D, без внешних библиотек: перспективная
камера, орбита мышью и колесом, сортировка граней по глубине, затенение по
направлению света, фасады с оконными проёмами, цоколь, плиты перекрытий,
площадка и дорожки. Три режима просмотра: здание целиком, внутренний срез до
выбранного этажа, разнесённые этажи. Помещение выбирается попаданием точки в
многоугольник грани. Пересчёт размеров — по `ResizeObserver`.

### 5.4 `yadro/chizma.js` — графики

SVG без библиотек, цвета берутся из токенов CSS: сглаженная область
(Catmull-Rom → кривые Безье), столбцы с сеткой, кольцевая диаграмма с итогом в
центре, мини-спарклайн для карточек показателей. Общая подсказка при наведении.

Карта — единственная внешняя библиотека, лежит локально в `assets/vendor/` и
используется двумя экранами.

## 6. Роли и доступ

Шесть ролей. Ключ роли вычисляется из названия должности в сессии, дальше всё
решает матрица.

| Роль | Ключ | Доступные разделы |
|---|---|---|
| Администратор | `admin` | все |
| Руководитель филиала | `filial` | все двенадцать разделов и настройки |
| Менеджер объектов | `obyekt` | панель, реестр, контроль доступа, осмотры, архив, карта, отчёты, задачи, документы, настройки |
| Инспектор осмотров | `nazorat` | панель, реестр, контроль доступа, осмотры, страхование, карта, отчёты, задачи, документы, настройки |
| Специалист-оценщик | `baholash` | панель, реестр, оценка, отчёты, задачи, документы, настройки |
| Юрист | `yurist` | панель, взыскание и суд, реестр, архив, отчёты, задачи, документы, настройки |

Проверка двухслойная:

1. **Раздел.** Каждая страница несёт `<body data-sahifa="…">`; `ROL_RUXSAT`
   решает, доступен ли раздел. Недоступный раздел не появляется ни в рельсе, ни
   в пилюлях шапки, а прямой переход по адресу ведёт на `xato-403.html`.
2. **Отдельные файлы.** `SAHIFA_MAXSUS` сужает доступ к тринадцати экранам
   поверх раздела: панели ролей, пользователи и их карточки, матрица ролей,
   журнал действий, интеграции, филиалы, мастер установки устройства.

Стартовая страница у каждой роли своя: `panel-<ключ>.html`, у администратора —
`panel.html`. Тот же список ролей повторён на сервере: запрос без сессии
возвращает 401, журнал действий не администратору — 403. Клиент и сервер
проверяют право независимо.

  закрывается заключением и подтверждающим материалом;
- **отчёт за период** `kirish-hisoboti.html`.

## 8. Жизненный цикл объекта

```
Просрочка по договору
  └─ Предупреждение → Исковое заявление → Судебное производство → Решение суда
      └─ Исполнение решения → Изъятие
          └─ Приём на баланс: акт, комиссия, документы
              └─ Хранение и контроль: осмотр · страхование · переоценка ·
                 контроль доступа · учёт расходов
                  └─ Снятие с контроля → Архив
```

Объект идёт по цепочке под одним номером вида `AK-YYYY/NNNN`. Этапы строго
последовательны, перескок через этап невозможен. Состояние объекта не задаётся
руками — оно выводится из этапа: «в обеспечении», «в процессе изъятия»,
«изъято», «хранится на балансе».

Продажа объекта в границы системы не входит: последний этап цепочки — **«На
балансе»**. Дальнейшее движение имущества ведётся вне этого контура.

## 9. Два режима данных

`yadro/api.js` — единственная точка доступа к данным. Экраны не вызывают `fetch`
напрямую, поэтому смена режима не требует правки ни одного экрана.

При загрузке модуль запрашивает `/api/salomat` с таймаутом 700 мс. Ответ — режим
`server`, отсутствие ответа — режим `snapshot`. Выбранный режим публикуется
событием `mkb:rejim`, оболочка показывает индикатор внизу рельса.

| Операция | Режим `server` | Режим `snapshot` |
|---|---|---|
| `royxat(коллекция, фильтр)` | `GET /api/<коллекция>` | массив из `MKB_DATA` плюс слой правок из браузера |
| `bitta(коллекция, id)` | `GET /api/<коллекция>/<id>` | поиск по тому же массиву |
| `yangilash(коллекция, id, поля)` | `PATCH` | правка ложится в слой, исходные данные не трогаются |
| `yangi(коллекция, объект)` | `POST` | новая запись добавляется в слой |
| `kirish` / `chiqish` / `sessiya` | токен сервера | сессия в браузере по выбранной роли |

В локальном режиме правки хранятся отдельным слоем поверх исходных данных:
запись помечается как изменённая, созданная или удалённая, а базовый массив
остаётся нетронутым. Каждое изменение попадает в журнал действий.

Контракт `server/server.js`:

```
GET   /api/salomat              доступность, без сессии
POST  /api/kirish               {login, parol, rol} → {token, ism, rol, filial}
GET   /api/<коллекция>          список; ?поле=значение — фильтр, ?q= — поиск по записи
GET   /api/<коллекция>/<id>     одна запись
POST  /api/<коллекция>          создание, идентификатор выдаётся при отсутствии
PATCH /api/<коллекция>/<id>     обновление полей
GET   /api/amallar              журнал действий, только администратор
```

Коды ответов: 401 — нет сессии, 403 — журнал запрошен не администратором,
404 — нет такой коллекции или записи, 405 — метод не поддержан. Полный контракт
серверной части — `docs/API.md`.
