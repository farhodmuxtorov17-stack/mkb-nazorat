# Система управления активами на балансе — архитектура

Рабочая система «Микрокредитбанка» для имущества, принятого на баланс банка:
приём на баланс, оформление права, оценка, защита пустующего объекта, осмотры,
подготовка к продаже, лот, договор и списание с баланса. До приёма на баланс
проблемный кредит ведётся в отдельном модуле «Взыскание и суд».

**105 страниц, 6 рабочих разделов, 4 рабочие роли и технический
администратор**, статический клиент без сборщика и необязательный локальный
сервер на Node.js без внешних пакетов.

Рельс сокращён по счёту, а не по составу. Раньше в нём было 10 разделов и
51 ссылка, и председатель видел все 51. Теперь любая роль видит не более шести
пунктов, а десять отчётных страниц свёрнуты в один центр отчётов. Ни одна
страница при этом не удалена: то, что ушло из рельса, открывается по ленте
вкладок раздела, из карточки объекта, из поиска `Ctrl+K` и по прямой ссылке
(2.1, там же открытый пункт по двум объединённым разделам).

### 1.2 Каркас страницы

Экраны — плоский список HTML-файлов в корне репозитория, без маршрутизатора.
Скелет одинаков у всех страниц оболочки:

```
<link rel="stylesheet" href="yadro/app.css?v=…">
<body data-sahifa="<ключ раздела>">
  <div class="qobiq">
    <nav class="yon" id="yon"></nav>                  ← рельс рисует app.js
    <div class="sahna">
      <header class="shapka" id="shapka"></header>    ← шапку рисует app.js
      <main class="kontent">  … разметка экрана …
```

Порядок подключения обязателен: каждый файл данных дописывает результат
предыдущего, `amal.js` опирается на оболочку.

```
malumot.js → malumot-qoshimcha.js → malumot-kengaytma.js → malumot-kirish.js →
malumot-indeks.js → tarjima.js → yadro/ikonlar.js → yadro/daraxt.js →
yadro/chizma.js → yadro/qollanma.js → yadro/api.js → yadro/app.js → yadro/amal.js
```

Все ссылки на общие файлы несут одну метку версии `?v=…`, поэтому кэш
сбрасывается разом. Девять страниц работают вне оболочки и помечены
`data-ochiq="1"`: `index.html`, `kirish.html`, `parol-tiklash.html`,
`parol-yangilash.html`, `oferta.html`, `maxfiylik.html`, `xato-403.html`,
`xato-404.html` и `taqdimot.html`.

### 1.3 Сервер

`server/server.js` — чистый Node.js:

- раздаёт статику из корня и обслуживает REST `/api/*` (контракт — `docs/API.md`);
- держит два хранилища: `shartli` (демонстрационное) и `mahalliy` (локальный
  реестр, только если есть `mahalliy/obyektlar.json`); исходные данные каждый раз
  берутся из модулей `malumot*.js`, правки пользователей хранятся слоем в
  `server/malumotlar/<источник>/ozgarishlar.json`;
- проверяет сессию (8 часов), роль, раздел, филиал и белый список полей;
- принимает файлы до 20 МБ в `server/malumotlar/<источник>/fayllar/`;
- ведёт журнал действий `amallar.json` (последние 5000 записей).

```
node server/server.js        →  http://127.0.0.1:8790
```

Каталоги `mahalliy/` и `server/` статикой наружу не отдаются; `mahalliy/`
доступен только с адреса самого компьютера.

## 2. Оболочка `yadro/app.js`

### 2.1 Разделы, роли, рельс

- **`BOLIMLAR`** — стартовая панель роли (`panel`) и шесть рабочих разделов:
  `aktivlar`, `nazorat`, `qiymat`, `sotuv`, `ishlar`, `hisobot`. Настройки
  (`sozlama`) рабочим разделом не считаются и рисуются отдельной группой внизу
  рельса.
- **`BOLIM_TAXALLUS`** — старые ключи `data-sahifa` (`himoya`, `korik`, `kn`,
  `baholash`, `realizatsiya`, `yuridik`, `vazifa`) приводятся к новым разделам,
  поэтому разметка страниц при объединении разделов не менялась.
- **`ROL_KALIT`, `ROL_RUXSAT`, `ROL_BOSH`, `SAHIFA_MAXSUS`** — матрица доступа
  (раздел 6). `MKB.huquq(bo'lim, "oqi"|"yoz"|"tasdiq")` отвечает, может ли
  текущая роль читать, записывать или утверждать; элементы с атрибутом
  `data-huquq="yoz"` скрываются, если права нет. `MKB.doira(список)` сужает
  выборку до филиала пользователя, если учётная запись привязана к филиалу.
- **`ROL_YANGI`, `ROL_ESKI`** — таблица переименования: сохранённая сессия или
  старая запись со снятой ролью (`Filial rahbari`, `Baholovchi`,
  `Realizatsiya mutaxassisi`, `Yurist`, `Xavfsizlik xizmati`,
  `Ko'rik inspektori`) приводится к действующей роли. Ту же таблицу держит
  сервер.
- **Рельс** плоский: один раздел — один пункт (`ROL_YON`), не более шести
  пунктов на роль (`ROL_YON_MAX`). Пункт без права не рисуется. Остальные
  страницы раздела перечислены в `MKB_DARAXT` и открываются по ленте вкладок,
  из поиска `Ctrl+K` (список берёт `yadro/ux.js` из того же `MKB_DARAXT`) и по
  прямой ссылке. **Лента вкладок** `nav.bolim-tablar` задана в разметке
  раздела, оболочка убирает закрытые вкладки. **Вкладки карточки объекта**
  рисует `MKB.obyektTablar` из `MKB_OBYEKT_TABLAR`. Центр отчётов
  дополнительно рисует карточку «Разделы» прямо из `MKB_DARAXT.hisobot`.

  Открытый пункт: в разделах `nazorat` и `sotuv`, собранных каждый из двух
  прежних разделов, лент по две. С `himoya.html` по ленте не попасть в план
  осмотров и инвентаризацию, с `realizatsiya.html` — в дела о взыскании и суд;
  на `panel-obyekt.html` ссылки на `undiruv.html` тоже нет. Перечень —
  `docs/EKRANLAR.md`.
- **Шапка**: быстрые разделы, поиск по реестру, переключатель UZ/RU, порядок
  работы для роли, уведомления, профиль.
- **Движки** `MKB.*`: `jadval` (поиск, фильтры, сортировка, постраничность,
  пустое состояние), `forma`, `modal`, `yonPanel`, `toast`, `boshHolat`,
  `barlar`, форматирование сумм и дат.

### 2.2 Перевод

`tarjimaQil()` обходит текстовые узлы и атрибуты `placeholder`, `title`,
`aria-label`, `alt`, `data-toast`, `data-yorliq`. Ключ словаря — точный текст
узла без пробелов по краям. Если ключа нет, применяются правила
`MKB_TARJIMA_QOIDALARI` (регулярное выражение → замена): суммы, сроки, счётчики
«N ta …», даты с месяцами, нормативные ссылки. Последними стоят составные
правила: текст вида «название · состояние» или «заголовок: значение» делится
на части, и каждая часть переводится отдельно. Исходный текст хранится в
`WeakMap`, возврат на узбекский точный. Перевод повторяется через 250 и
1000 мс; содержимое, которое экран дорисовывает позже, переводится вызовом
`tarjimaQil(узел)` из самого экрана.

Внутри `[data-tarjimasiz]` текст не переводится, кроме единиц после числа
(`mkbBirlikTarjima`): сумы, дни, месяцы, часы, «ta», м², а также Вт, Вт·ч,
кВт·ч/м², км/ч, мм, мс и «3-chorak 2026» → «3-й квартал 2026 г.».
Фрагмент, прилипший к разделителю («· Vositachi saytlar»), переводится по
частям. Ключ, узбекский текст которого больше не встречается ни в одной
странице, скрипте или файле данных, из словаря удаляется.

Проверка полноты перевода — `node tests/tarjima.mjs` (раздел 10).

`MKB_DATA.MANBA`:

  записи строятся детерминированно, все даты — относительно `bugun()`. На
  21.09.2026: 48 дел взыскания (40 активных), 81 лот, 44 предложения,
  43 договора, 15 договоров аренды, 921 осмотр, 277 полисов, 265 оценок,

  190 уведомлений. Фотографий объектов в демонстрационных данных нет.
- **`mahalliy`** — фактический реестр банка из `mahalliy/obyektlar.json`

  начинаются пустыми, экраны показывают честное пустое состояние.

### 3.4 Сроки и резерв

`muddatHisobi(актив)` считает от даты постановки на баланс:

- льгота по налогу на имущество — 6 месяцев (`soliqImtiyozOy`);
- предел безнадёжной категории — 365 дней для имущества из залога и
  1095 дней для иного неиспользуемого имущества (`chegaraKuni()`, основание
  приёма `garov: false`);
- статусы срока: в льготе, в норме, менее 90 дней до безнадёжной, безнадёжная,
  более 3 лет, списан, дата не указана.

`zaxiraHisobi(актив)`: после предела резерв — 100% балансовой стоимости
(утверждённое правило ЦБ № 2696). Промежуточные ставки до предела берутся из
`PARAMETRLAR` с признаком `taxminiy` и показываются с пометкой «на
утверждении бухгалтерии». Без даты или стоимости резерв не рассчитывается и
показывается как «не указано», а не нулём.

### 3.5 Взыскание отдельно от баланса

`UNDIRUV_ISHLAR` — дела до приёма на баланс: кредитный договор, долг, залог,
этап (предупреждение → иск → суд → решение → исполнение → приём на баланс).
`SUD_MAJLISLAR`, `RESTRUKTURIZATSIYA`, `MULOQOTLAR` ссылаются на дело по
`ishId`. Последний этап открывает мастер приёма `qabul-boshlash.html?ish=ID`:
основание приёма и номер решения суда подставляются из дела. После приёма дело
закрывается, в нём остаётся `aktivId`, а в активе — `balans.undiruvIshId`.

### 3.6 Согласованность

`moslikTekshiruvi()` возвращает список нарушений; на исправных данных он пуст.
Проверяются: дата и стоимость постановки на баланс, известные статус, этап и
вид фото, признак оценки, отсутствие площади и коммунальных услуг у актива без
здания, путь к фото (только реальные файлы: `mahalliy/`, `fayllar/`, `api/`,
`data:`, `blob:`), уникальность идентификаторов, разрешимость `obyektId` во
вторичных коллекциях, связь заседаний с делами, не менее 30 дней от объявления
до торгов (ПКМ № 18), сходимость графика платежей с ценой договора, финансовый
результат архивной записи, покрытие реестра разрезом по регионам.

## 5. Бизнес-операции `yadro/amal.js`

Экраны не реализуют правила сами, а вызывают общие операции:

| Операция | Что делает |
|---|---|
| `MKB.tasdiq.qabul(id)`, `MKB.tasdiq.rad(id, sabab)` | Решение по вопросу из очереди «Решения»: предложение покупателя, снижение цены лота, результат оценки, приём залога на баланс |
| `MKB.chiqim(obyektId, asos)`, `MKB.chiqim.sorov(...)` | Списание с баланса с записью в архив и расчётом финансового результата; без права утверждения — запрос руководству |
| `MKB.lot.tekshir/yarat(...)` | Проверка и создание лота: оценка, цены, не менее 30 дней от объявления до торгов |
| `MKB.shartnoma.yarat(taklifId)` | Договор по утверждённому предложению: график платежей, срок оплаты победителем 5 рабочих дней, договор — 10 |
| `MKB.hodisa.yarat(...)` | Происшествие с уведомлением ответственного |
| `MKB.qoidalar.natijalar()`, `ishgaTushir()` | Движок правил: по `QOIDALAR` создаёт уведомления и задачи (безнадёжная категория, полис, оценка, осмотр, устройство без связи, отчёт ЦБ) |

Все записи идут через `MKBapi`, поэтому одинаково работают в обоих режимах.

### 5.1 Печатные формы и импорт

**Модель листа.** Страница собирает объект `{tur, sarlavha, raqam, sana, joy, obyekt,
bolimlar: [{kv | jadval | matn}], fotolar, fotoKerak, komissiya, qoralama, havola}` и
передаёт его в `MKB.dalolatnoma.chiz(joy, m)` (форма на своей странице) или
`MKB.dalolatnoma.chop(m)` (печать с чужой страницы: лист временно добавляется в
конец `body`, остальная страница при печати скрыта). Значения ячеек: строка — данные
(не переводятся), `{t}` — текст для перевода, `{html}` — готовая разметка.
Пустая строка — поле для ручного заполнения на бумаге.

**Код проверки** = первые 12 шестнадцатеричных символов SHA-256 от канонического JSON
модели: номер, дата (кроме паспорта, где дата — день печати), тексты разделов в
исходном узбекском виде, идентификаторы фото, состав комиссии, признак черновика.
В код не входят язык интерфейса, время печати и адреса изображений, поэтому
русская и узбекская копии одного акта дают один код. QR содержит адрес формы с
`kod`; страница пересчитывает код и показывает только «совпадает / не совпадает».
SHA-256 реализован в модуле: он работает и на внутреннем HTTP-сервере, где
`crypto.subtle` браузером закрыт.

**Три формы с других страниц** собираются в модуле (`MKB.dalolatnoma.shakl(tur, p)`):
`chiqim` (заявка `TASDIQLAR` или запись `ARXIV`), `topshirish` (`SHARTNOMALAR`),
`hodisa` (`HODISALAR` или `XAVFSIZLIK_HODISALARI`). Странице достаточно вызвать
`MKB.dalolatnoma.tugma(konteyner, tur, p)`; ссылка из QR (`?dalolatnoma=<tur>&kod=`)
проверяется модулем без участия страницы.

**Штампы фото осмотра** хранятся в пункте `chekList` с `tur: "gps"`: `vaqt` (время
подписи), координаты страницы и `suratlar: [{faylId, vaqt, suratVaqti, lat, lng,
aniqlik, manba: "exif" | "qurilma", masofa}]`. Отдельной схемы не требуется, другие
экраны показывают этот пункт одной строкой «Joylashuv».

**Импорт.** `MKB.jadvalImport(cfg)` открывает окно ядра и добавляет к нему `.xlsx`:
файл распаковывается `DecompressionStream("deflate-raw")`, первый лист переводится в
CSV и передаётся обработчику ядра, поэтому сопоставление столбцов, проверка строк,
подтверждение и запись остаются в ядре. Даты Excel (серийные числа со стилем даты)
приводятся к `dd.mm.yyyy`, числа — к записи с запятой. Кнопка «Namuna fayl» строит
несжатый `.xlsx` из `cfg.ustunlar` и `cfg.namuna`, второй лист — правила столбцов.
Страница отвечает только за правила строки и запись; правило четырёх глаз сохраняется
самой записью: актив — «Rasmiylashtirilmoqda», оценка — заявка `baho`.

### 5.2 Отчёты за период и сверка с АБС

`hisobot-davr.js` работает без DOM и загружается в тесте Node
(`tests/davr.test.js`).

- **Период** — неделя с понедельника по воскресенье (ISO 8601), месяц, квартал,
  год. Незавершённый период сравнивается с тем же числом дней предыдущего.
- **Движение** за период: принято на баланс, подписанные договоры, поступления
  (аванс в день договора и оплаченные месяцы графика; пока АБС не подключена,
  датой платежа считается дата по графику), выбытие с баланса, решения,
  происшествия, просроченные осмотры на конец периода.
- **Где используется**: `haftalik.html` (итоги недели для руководства),
  `panel.html` (отчёт для наблюдательного совета за месяц, квартал или год),
  `panel-moliya.html` (сверка с АБС). Одно число не может разойтись на двух
  страницах.
- **Сверка с АБС**: бухгалтерия вводит остаток счёта 16701 из
  оборотно-сальдовой ведомости на конец месяца; необязательная аналитическая
  выписка (CSV: номер в реестре, дата постановки, сумма) сопоставляется с
  реестром построчно. Разница требует пояснения, отчёт ЦБ сдаётся после
  отметки о сверке (`mbTopshirishTayyormi`). Сохранение отметки в записи отчёта
  ЦБ требует поля `solishtirish` в схеме; пока его нет, акт сверки печатается
  и подписывается.

## 6. Роли и доступ

Ролей пять: четыре рабочие и технический администратор. Снятые роли не удалены
как работа — их обязанности перешли к оставшимся ролям.

| Роль | Ключ | Стартовая страница | Что ведёт |
|---|---|---|---|
| Rahbariyat | `rahbariyat` | `panel.html` | председатель, член правления, управляющий филиалом: видит всё и утверждает решения; формы не заполняет |
| Obyekt menejeri | `obyekt` | `panel-obyekt.html` | реестр, приём на баланс, документы, заказ оценки, продажа, аренда, дела о взыскании |
| Ko'rik va xavfsizlik inspektori | `nazorat` | `panel-nazorat.html` | осмотры, инвентаризация, устройства, происшествия, охрана, доступ на объект |
| Buxgalteriya va risk | `buxgalteriya` | `panel-moliya.html` | резерв, налоги, отчёт ЦБ, платежи, нормативные параметры |
| Administrator | `admin` | `panel.html` | учётные записи, роли, настройки; не деловая роль |

Куда ушла работа снятых ролей: `Filial rahbari` → `Rahbariyat` с привязкой к
филиалу (`MKB.doira` оставляет только записи этого филиала); `Baholovchi` и
`Realizatsiya mutaxassisi` → `Obyekt menejeri`; `Yurist` → `Obyekt menejeri`
(дела о взыскании и суд); `Xavfsizlik xizmati` и `Ko'rik inspektori` →
`Ko'rik va xavfsizlik inspektori`. Таблица переименования — `ROL_YANGI` в
`yadro/app.js`, такая же на сервере.

Права по разделам (`ROL_RUXSAT`; `o` — чтение, `y` — запись, `t` —
утверждение):

| Роль | panel | aktivlar | nazorat | qiymat | sotuv | hisobot | ishlar | sozlama |
|---|---|---|---|---|---|---|---|---|
| rahbariyat | o | ot | ot | ot | ot | o | oyt | o |
| obyekt | o | oy | oyt | oy | oy | o | oy | o |
| nazorat | o | o | oy | o | o | o | oy | o |
| buxgalteriya | o | o | o | oyt | o | oy | oy | o |
| admin | oyt | oyt | oyt | oyt | oyt | oyt | oyt | oyt |

всем разделам; правило четырёх глаз на него всё равно распространяется (6.1).

Рельс роли (`ROL_YON`, не более шести пунктов):

Проверка в три слоя: раздел (`data-sahifa` и `ROL_RUXSAT`, буквы `o`/`y`/`t` —

может изменить запись чужого филиала.

### 6.1 Четыре глаза

Запрашивает и решает — всегда разные сотрудники. Автор запроса не утверждает
свой запрос, и администратор тоже (`MKB_TORT_KOZ.ozimi` в `yadro/amal.js`,
такая же проверка на сервере, 403 на попытку). Проверка персональная, а не
ролевая: сравниваются логин и имя автора, а не его роль.

Право на решение задано двумя способами. У записи `TASDIQLAR` есть поле
`masulRol`; если оно заполнено, решение принимает только эта роль, и права `t`
в разделе для этого недостаточно (`rolHalQiladimi`). `MKB.tasdiq.sorov`
подставляет `masulRol: "Rahbariyat"` по умолчанию, поэтому все шесть видов
запросов уходят руководству. Если `masulRol` пуст, решает тот, у кого есть `t`
в разделе из `TASDIQ_BOLIM`.

| Запрос | Раздел | Кто запрашивает | Кто решает |
|---|---|---|---|
| Приём на баланс (`qabul`) | `aktivlar` | obyekt | rahbariyat (`masulRol`) |
| Списание с баланса (`chiqim`) | `aktivlar` или `sotuv` | obyekt | rahbariyat (`masulRol`) |
| Предложение покупателя (`taklif`) | `sotuv` | obyekt | rahbariyat (`masulRol`) |
| Снижение начальной цены лота (`pasaytirish`) | `sotuv` | obyekt | rahbariyat (`masulRol`) |
| Отчёт об оценке (`baho`) | `qiymat` | obyekt | rahbariyat (`masulRol`) |
| Ставка резерва и нормативные параметры (`zaxira`) | `qiymat` | buxgalteriya (`TASDIQ_SORUVCHI`) | rahbariyat (`masulRol`) |
| Доступ на объект (`kirish-soravi.html`) | `nazorat` | nazorat | obyekt или rahbariyat (`t` в разделе) |

Заявка на доступ — единственный поток без `masulRol`: её закрывает любой, у кого
есть `t` в разделе `nazorat`, то есть менеджер объектов или руководство. Так
инспектор не ждёт правление ради одного пропуска, но и не пускает себя сам.

До утверждения значение, зависящее от запроса, помечается как
«ориентировочное» и в этом виде попадает в расчёты, панели и отчёты.

Замещение: если у утверждающего назначен заместитель, тот решает от его имени
(`vakolat` возвращает `{tur: "o'rinbosar"}`), но правило четырёх глаз остаётся —
заместитель не может закрыть запрос, автором которого является он сам.

### 6.2 Администрирование

Правила раздела «Настройки» собраны в `boshqaruv.js` и проверяются без
браузера (`tests/boshqaruv.test.js`).

- **Состояние системы** (`tizim-holati.html`, только администратор): что требует
  внимания (активы у заблокированных сотрудников, пересмотр прав за квартал,
  незаданные сроки хранения, устройства без сигнала более 24 часов, давность
  полной копии, отклонённые входы за 7 дней), актуальность коллекций по истории
  действий, давность сигналов устройств, полная копия с SHA-256, режим, версия
  и проверка выхода в интернет.
- **Пересмотр прав** раз в квартал (`foydalanuvchilar.html`): заблокированные
  сотрудники с активами, записи без входа 90 дней, лишние администраторы.
  Активы передаются другому менеджеру объектов, каждое изменение пишется в
  историю действий; итог — акт пересмотра.
- **Сроки хранения** (`sozlamalar.html`): вид данных, срок, правовое основание,
  что происходит по истечении (ЗРУ-547). Уведомление о конфиденциальности
  (`maxfiylik.html`) берёт сроки из этой таблицы. Записи посетителей с истёкшим
  сроком обезличиваются. Запрос сотрудника о своих данных регистрируется,
  становится задачей администратора, ответ — распечатанная выписка.
- **Интеграции** (`integratsiyalar.html`): 15 внешних систем (АБС, E-auksion,
  кадастр, СБДД, БПИ, налоговая, портал ЦБ, my.gov.uz, E-IMZO, Active Directory,
  SMS-шлюз, Telegram, пульт охраны, NVR и IoT-шлюз, коммунальные поставщики):
  потоки данных, условия подключения, ответственный и статус. Статус
  «Подключено» ставится только после реального поступления данных; пока
  система не подключена, поле вводится вручную и рядом указан источник.
- **История действий** (`amallar-tarixi.html`): фильтр по активу, выгрузка CSV
  с числом записей и контрольной суммой SHA-256 в конце файла.

  namuna ko'rsatilmaydi», остальная страница работает.
- Координата объекта округляется до 0,1° (около 11 км) до отправки в Open-Meteo.
- Сообщение MQTT идёт в схеме событий платформы `mkb.qurilma.voqea/1`, поле
  `obyektId` пустое, топик случайный. Входящее сообщение вне схемы или
  больше 2 КБ отбрасывается. В банке вместо публичного брокера работает свой:
  TLS, отдельный логин или сертификат на каждое устройство, ACL по топикам.
- Расчёты без сети (`MKB_JONLI_SOF`, тест `tests/jonli.test.js`): литиевый
  аккумулятор не заряжается ниже 0 °C; суточная выработка = радиация ×
  мощность панели × 0,7; основание для внепланового осмотра — порывы выше
  72 км/ч, осадки больше 20 мм за 24 часа или мороз ниже −10 °C. Система
  осмотр не создаёт, решение принимает инспектор.
- Камеры, оставленные без защиты или найденные поиском (Shodan, Insecam и
  подобные), не используются: это несанкционированный доступ. Карточка
  показывает проверенные и отклонённые источники с причиной.

Где видно: центр мониторинга (карточка «Ulanish namunasi»), список устройств
(тестовое устройство), карточка устройства и вкладка «Himoya» объекта (погода
района), интеграции (проверка MQTT), состояние системы (проверка выхода в
интернет).

## 8. Путь актива

```
Дело взыскания (UNDIRUV_ISHLAR)
  └─ предупреждение → иск → суд → решение → исполнение
      └─ Приём на баланс: основание, акт, комиссия, счётчики, ключи
          └─ Оформление права: кадастр / ГУБДД (10 дней для транспорта)
              └─ Оценка → Подготовка к продаже → Лот (E-auksion) или прямая продажа,
                 рассрочка, лизинг, аренда до продажи, передача в Госактив
                  └─ Договор и платежи → Списание с баланса → Архив
```

Параллельно на всём пути: осмотры, страхование, охрана и устройства,
коммунальные услуги, расходы на содержание, налоги, резерв.

## 9. Локальный реестр и фото

### 9.1 Импорт

```
python vositalar/import_taqdimot.py "<путь к презентации>.pptx"
```

Сценарий пишет `mahalliy/obyektlar.json` (объекты и филиалы) и фото в
`mahalliy/`. Каталог внесён в `.gitignore` и в репозиторий не попадает.

### 9.2 Чтение

`malumot.js` запрашивает `mahalliy/obyektlar.json` только когда страница открыта
с `localhost`, `127.0.0.1` или `[::1]`, и только если не выбран
демонстрационный режим (`localStorage["mkb-manba"] = "shartli"`). Из записи
берутся название, адрес, вид, регион, филиал, прежний владелец, дата и стоимость
постановки на баланс, цена продажи, площади и фото. Координата ставится в центр
региона с `aniq: false`, пока точное место не введено вручную.

### 9.3 Гарантии конфиденциальности

1. `mahalliy/` не попадает в репозиторий и публикуемую копию.
2. Файл читается только с адреса самого компьютера; сервер отдаёт `/mahalliy/`
   лишь запросам с `127.0.0.1` и `::1`.
3. Автоматические проверки работают на демонстрационных данных; тест локального
   режима использует вымышленные записи, а не реальный файл.
4. Правки, журнал и файлы локального и демонстрационного режимов хранятся
   раздельно (суффикс `-mahalliy` в ключах браузера, отдельные каталоги на сервере).

### 9.4 Запуск на рабочем компьютере

`ishga-tushirish.cmd` в корне проекта: двойной щелчок запускает
`python -m http.server 8777 --bind 127.0.0.1` из папки проекта и открывает
`http://127.0.0.1:8777/kirish.html`. Если порт уже занят, открывается только
браузер. Закрытие окна останавливает сервер. Так система показывается с
фактическим реестром и фото без выхода в сеть.
