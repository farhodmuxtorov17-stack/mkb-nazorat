# Система управления активами на балансе — архитектура

Рабочая система «Микрокредитбанка» для имущества, принятого на баланс банка:
приём на баланс, оформление права, оценка, защита пустующего объекта, осмотры,
подготовка к продаже, лот, договор и списание с баланса. До приёма на баланс
проблемный кредит ведётся в отдельном модуле «Взыскание и суд».

**100 страниц, 10 разделов, 10 ролей**, статический клиент без сборщика и
необязательный локальный сервер на Node.js без внешних пакетов.

### 1.2 Каркас страницы

Экраны — плоский список HTML-файлов в корне репозитория, без маршрутизатора.
Скелет одинаков у всех страниц оболочки:

```
<link rel="stylesheet" href="yadro/app.css?v=…">
<body data-sahifa="<ключ раздела>">
  <div class="qobiq">
    <nav class="yon" id="yon"></nav>                  ← рельс рисует app.js
    <div class="sahna">
      <header class="shapka" id="shapka"></header>    ← шапку рисует app.js
      <main class="kontent">  … разметка экрана …
```

Порядок подключения обязателен: каждый файл данных дописывает результат
предыдущего, `amal.js` опирается на оболочку.

```
malumot.js → malumot-qoshimcha.js → malumot-kengaytma.js → malumot-kirish.js →
malumot-indeks.js → tarjima.js → yadro/ikonlar.js → yadro/daraxt.js →
yadro/chizma.js → yadro/qollanma.js → yadro/api.js → yadro/app.js → yadro/amal.js
```

Все ссылки на общие файлы несут одну метку версии `?v=…`, поэтому кэш
сбрасывается разом. Семь страниц работают вне оболочки и помечены
`data-ochiq="1"`: `index.html`, `kirish.html`, `parol-tiklash.html`,
`parol-yangilash.html`, `xato-403.html`, `xato-404.html` и `taqdimot.html`.

### 1.3 Сервер

`server/server.js` — чистый Node.js:

- раздаёт статику из корня и обслуживает REST `/api/*` (контракт — `docs/API.md`);
- держит два хранилища: `shartli` (демонстрационное) и `mahalliy` (локальный
  реестр, только если есть `mahalliy/obyektlar.json`); исходные данные каждый раз
  берутся из модулей `malumot*.js`, правки пользователей хранятся слоем в
  `server/malumotlar/<источник>/ozgarishlar.json`;
- проверяет сессию (8 часов), роль, раздел, филиал и белый список полей;
- принимает файлы до 20 МБ в `server/malumotlar/<источник>/fayllar/`;
- ведёт журнал действий `amallar.json` (последние 5000 записей).

```
node server/server.js        →  http://127.0.0.1:8790
```

Каталоги `mahalliy/` и `server/` статикой наружу не отдаются; `mahalliy/`
доступен только с адреса самого компьютера.

## 2. Оболочка `yadro/app.js`

### 2.1 Разделы, роли, рельс

- **`BOLIMLAR`** — девять рабочих разделов; десятый, настройки (`sozlama`),
  рисуется отдельной группой внизу рельса.
- **`ROL_KALIT`, `ROL_RUXSAT`, `ROL_BOSH`, `SAHIFA_MAXSUS`** — матрица доступа
  (раздел 6). `MKB.huquq(bo'lim, "oqi"|"yoz"|"tasdiq")` отвечает, может ли
  текущая роль читать, записывать или утверждать; элементы с атрибутом
  `data-huquq="yoz"` скрываются, если права нет. `MKB.doira(список)` сужает
  выборку до филиала пользователя для руководителя филиала.
- **Рельс** собирается из `MKB_DARAXT`; пункт без права не рисуется.
  **Лента вкладок** `nav.bolim-tablar` задана в разметке раздела, оболочка
  убирает закрытые вкладки. **Вкладки карточки объекта** рисует
  `MKB.obyektTablar` из `MKB_OBYEKT_TABLAR`.
- **Шапка**: быстрые разделы, поиск по реестру, переключатель UZ/RU, порядок
  работы для роли, уведомления, профиль.
- **Движки** `MKB.*`: `jadval` (поиск, фильтры, сортировка, постраничность,
  пустое состояние), `forma`, `modal`, `yonPanel`, `toast`, `boshHolat`,
  `barlar`, форматирование сумм и дат.

### 2.2 Перевод

`tarjimaQil()` обходит текстовые узлы и атрибуты `placeholder`, `title`,
`aria-label`, `alt`, `data-toast`, `data-yorliq`. Ключ словаря — точный текст
узла без пробелов по краям. Если ключа нет, применяются правила
`MKB_TARJIMA_QOIDALARI` (регулярное выражение → замена): суммы, сроки, счётчики
«N ta …», даты с месяцами, нормативные ссылки. Последними стоят составные
правила: текст вида «название · состояние» или «заголовок: значение» делится
на части, и каждая часть переводится отдельно. Исходный текст хранится в
`WeakMap`, возврат на узбекский точный. Перевод повторяется через 250 и
1000 мс; содержимое, которое экран дорисовывает позже, переводится вызовом
`tarjimaQil(узел)` из самого экрана.

Проверка полноты перевода — `node tests/tarjima.mjs` (раздел 10).

### 3.2 Два источника данных

`MKB_DATA.MANBA`:

- **`shartli`** — демонстрационные данные. 267 условных активов и связанные
  записи строятся детерминированно, все даты — относительно `bugun()`. На
  21.09.2026: 48 дел взыскания (40 активных), 81 лот, 44 предложения,
  43 договора, 15 договоров аренды, 921 осмотр, 277 полисов, 265 оценок,
  135 договоров охраны, 334 точки доступа, 473 устройства, 191 задача,
  190 уведомлений. Фотографий объектов в демонстрационных данных нет.
- **`mahalliy`** — фактический реестр банка из `mahalliy/obyektlar.json`
  (раздел 9). Читаются только объекты и филиалы; остальные коллекции
  начинаются пустыми, экраны показывают честное пустое состояние.

### 3.3 Запись актива `YOZUVLAR`

Актив — имущество на балансе. Полей кредита (долг, просрочка, категория
кредита) в записи нет: они живут в деле взыскания.

| Группа | Поля |
|---|---|
| корень | `id`, `nom`, `qisqa`, `tur`, `turKalit`, `rasmTuri`, `binoli`, `hudud`, `hududKod`, `hududToliq`, `tuman`, `manzil`, `joy {lat, lng, aniq}`, `filial`, `filialKod`, `sobiqEga`, `holat`, `bosqich`, `masul`, `konservatsiya`, `izoh`, `tarix[]` |
| `balans` | `sana`, `qiymat` (млн сум), `hisobvaraq`, `qabulAsosi`, `asosHujjat {raqam, sana}`, `yopilganQarz`, `ixtiyoriyTopshirish`, `undiruvIshId` |
| `qiymat` | `bozor`, `tugatish`, `baholanmagan`, `bahoSana`, `baholovchi` |
| `maydon` | `yer`, `qurilishOsti`, `foydali` (у актива без здания — нули) |
| `huquq` | `kadastrRaqami`, `qaydSana`, `reyestrKochirma`, `taqiqlar[]`, `yerHuquqiTuri`, `davlatRaqami`, `vin`, `texPasport`, `yhxxQaydSana`, `aholiPunktiToifasi` |
| `kommunal[]` | по услуге (электричество, газ, вода): состояние, счётчик, показание, пломба, лицевой счёт, долг прежнего владельца, справка, техусловия |
| `himoya`, `sotuv`, `qabul` | вид охраны и шаблон защиты; статус продажи и лот; акт приёма, комиссия, ключи, оборудование |
| фото | `rasm`, `rasmKichik`, `rasmlar[] {yol, tur}`, `rasmManba`, `rasmUmumiy` |

Производные поля не сохраняются и считаются при каждом обращении:
`muddat` (сроки), `zaxira` (резерв), `mulk` (сводка для списков), `holatInfo`.

Статусы: Balansda, Rasmiylashtirilmoqda, Sotuvga tayyorlanmoqda, Lotda, Ijarada,
Bo'lib to'lashda, Davaktivga o'tkazilgan, Chiqarildi. Этапы пути актива:
приём, оформление права, оценка, подготовка к продаже, лот, договор, списание.
Вид фото `rasmTuri` — один из 12 ключей `TUR_KALITLAR`.

### 3.4 Сроки и резерв

`muddatHisobi(актив)` считает от даты постановки на баланс:

- льгота по налогу на имущество — 6 месяцев (`soliqImtiyozOy`);
- предел безнадёжной категории — 365 дней для имущества из залога и
  1095 дней для иного неиспользуемого имущества (`chegaraKuni()`, основание
  приёма `garov: false`);
- статусы срока: в льготе, в норме, менее 90 дней до безнадёжной, безнадёжная,
  более 3 лет, списан, дата не указана.

`zaxiraHisobi(актив)`: после предела резерв — 100% балансовой стоимости
(утверждённое правило ЦБ № 2696). Промежуточные ставки до предела берутся из
`PARAMETRLAR` с признаком `taxminiy` и показываются с пометкой «на
утверждении бухгалтерии». Без даты или стоимости резерв не рассчитывается и
показывается как «не указано», а не нулём.

### 3.5 Взыскание отдельно от баланса

`UNDIRUV_ISHLAR` — дела до приёма на баланс: кредитный договор, долг, залог,
этап (предупреждение → иск → суд → решение → исполнение → приём на баланс).
`SUD_MAJLISLAR`, `RESTRUKTURIZATSIYA`, `MULOQOTLAR` ссылаются на дело по
`ishId`. Последний этап открывает мастер приёма `qabul-boshlash.html?ish=ID`:
основание приёма и номер решения суда подставляются из дела. После приёма дело
закрывается, в нём остаётся `aktivId`, а в активе — `balans.undiruvIshId`.

### 3.6 Согласованность

`moslikTekshiruvi()` возвращает список нарушений; на исправных данных он пуст.
Проверяются: дата и стоимость постановки на баланс, известные статус, этап и
вид фото, признак оценки, отсутствие площади и коммунальных услуг у актива без
здания, путь к фото (только реальные файлы: `mahalliy/`, `fayllar/`, `api/`,
`data:`, `blob:`), уникальность идентификаторов, разрешимость `obyektId` во
вторичных коллекциях, связь заседаний с делами, не менее 30 дней от объявления
до торгов (ПКМ № 18), сходимость графика платежей с ценой договора, финансовый
результат архивной записи, покрытие реестра разрезом по регионам.

## 4. Индекс контроля объекта

Показатель 0–100, пересчитывается из текущих данных (`malumot-indeks.js`).

| Проверка | Вес | Норма |
|---|---|---|
| Актуальность осмотра | 25 | здание — раз в 90 дней, транспорт и оборудование — раз в 30 |
| Страховая защита | 25 | действующий полис, покрытие не ниже оценки |
| Актуальность оценки | 20 | раз в 12 месяцев |
| Полнота документов | 15 | обязательные документы текущего этапа (`MAJBURIY_HUJJATLAR`) |
| Охрана и устройства | 15 | договор охраны или устройства на связи, нет открытых происшествий |

Публичные точки: `nazoratIndeksi(объект)`, `nazoratJamlama()`,
`nazoratKeshTozala()` — сброс кэша после записи.

## 5. Бизнес-операции `yadro/amal.js`

Экраны не реализуют правила сами, а вызывают общие операции:

| Операция | Что делает |
|---|---|
| `MKB.tasdiq.qabul(id)`, `MKB.tasdiq.rad(id, sabab)` | Решение по вопросу из очереди «Решения»: предложение покупателя, снижение цены лота, результат оценки, приём залога на баланс |
| `MKB.chiqim(obyektId, asos)`, `MKB.chiqim.sorov(...)` | Списание с баланса с записью в архив и расчётом финансового результата; без права утверждения — запрос руководству |
| `MKB.lot.tekshir/yarat(...)` | Проверка и создание лота: оценка, цены, не менее 30 дней от объявления до торгов |
| `MKB.shartnoma.yarat(taklifId)` | Договор по утверждённому предложению: график платежей, срок оплаты победителем 5 рабочих дней, договор — 10 |
| `MKB.hodisa.yarat(...)` | Происшествие с уведомлением ответственного |
| `MKB.qoidalar.natijalar()`, `ishgaTushir()` | Движок правил: по `QOIDALAR` создаёт уведомления и задачи (безнадёжная категория, полис, оценка, осмотр, устройство без связи, отчёт ЦБ) |

Все записи идут через `MKBapi`, поэтому одинаково работают в обоих режимах.

проверяет её до чтения хранилища; руководитель филиала не может изменить


коммунальные услуги, расходы на содержание, налоги, резерв.

## 9. Локальный реестр и фото

### 9.1 Импорт

```
python vositalar/import_taqdimot.py "<путь к презентации>.pptx"
```

Сценарий пишет `mahalliy/obyektlar.json` (объекты и филиалы) и фото в
`mahalliy/`. Каталог внесён в `.gitignore` и в репозиторий не попадает.

### 9.2 Чтение

`malumot.js` запрашивает `mahalliy/obyektlar.json` только когда страница открыта
с `localhost`, `127.0.0.1` или `[::1]`, и только если не выбран
демонстрационный режим (`localStorage["mkb-manba"] = "shartli"`). Из записи
берутся название, адрес, вид, регион, филиал, прежний владелец, дата и стоимость
постановки на баланс, цена продажи, площади и фото. Координата ставится в центр
региона с `aniq: false`, пока точное место не введено вручную.

### 9.3 Гарантии конфиденциальности

1. `mahalliy/` не попадает в репозиторий и публикуемую копию.
2. Файл читается только с адреса самого компьютера; сервер отдаёт `/mahalliy/`
   лишь запросам с `127.0.0.1` и `::1`.
3. Автоматические проверки работают на демонстрационных данных; тест локального
   режима использует вымышленные записи, а не реальный файл.
4. Правки, журнал и файлы локального и демонстрационного режимов хранятся
   раздельно (суффикс `-mahalliy` в ключах браузера, отдельные каталоги на сервере).

### 9.4 Запуск на рабочем компьютере

`ishga-tushirish.cmd` в корне проекта: двойной щелчок запускает
`python -m http.server 8777 --bind 127.0.0.1` из папки проекта и открывает
`http://127.0.0.1:8777/kirish.html`. Если порт уже занят, открывается только
браузер. Закрытие окна останавливает сервер. Так система показывается с
фактическим реестром и фото без выхода в сеть.
